# 本草辨证：面向中医教学与科研的知识检索辅助工具

> **定位：**面向**中医专业教学与科研场景**的知识检索与证型辨析辅助工具。服务对象为中医专业学生、规培医师与科研人员，用于证型知识查阅、证据追溯与检索方法教学。**不是医疗器械、诊断系统或处方工具**，不构成医学诊断，不作为临床决策依据。知识库包含 37 个证型条目（248 个症状词、107 条口语同义词映射），展示时应如实说明数据规模与局限。

> **竞赛提交材料见《docs/竞赛提交材料.md》**：按竞赛"作品要求"六条逐条对应（学科需求分析 / AI 技术应用方案 / 作品功能说明 / 创新点与传统方式对比 / 可行性与推广方案 / 规范与伦理），本文件提供技术细节与实验数据。

## 辨证训练（出题引擎）

在原有"知识检索"之上新增"辨证训练"模块，形成"查证型 → 练辨证"的教学闭环。

**设计原则：生成与判定分离。**

| 环节 | 由谁决定 | 说明 |
|---|---|---|
| 标准答案 | **病历标注 + 证型知识库** | 不由大模型自由发挥 |
| 题干文字 | 大模型 | 把真实病历改写成题面 |
| 干扰项 | 知识库候选池（同范畴相近证型）| 禁止自造证型名 |
| 选项位置 | **程序随机打乱** | 见下 |
| 质量校验 | 程序（6 项核心 + 2 项加分）| 答案一致性、白名单、干扰项来源等 |

**为什么需要程序打乱选项？** 提示词要求"标准答案 + 三个干扰项"，模型会习惯性把答案放在第一位。
实测若不打乱，正确选项为 A 的比例高达 70%（10 题样本）。因此在题目生成后由程序执行 `shuffle` 并同步更新
`answer_index`，实测分布回到 A/B/C/D ≈ 25%/25%/25%/25%（8 题样本）。
**这类规律性偏差若不处理，学生可直接靠位置猜答案，题目即失去训练价值。**

**出题范围：** 中医内科学。从全量 54,152 条病历中按疾病命名规律筛出内科 29,961 条（143 个证型，权威定义覆盖率 100%），
再取病历数 ≥ 30 且有"典型表现"文本的 72 个核心证型（25,750 条素材）作为出题池，分层配额共 438 题。

**素材索引：** 只存"文件 + 行号"，出题时回读原文，26,474 条病历引用仅 1.4 MB（相较存全文缩小 22 倍）。

## 项目亮点

- **输入风格路由：**先判定输入是口语描述还是电子病历体，再选方法。依据是实测的互补性——口语体下 TF-IDF 检索 91.9% 而分类器仅 5.4%；病历体下分类器 93.0% 而检索仅 12.7%。判据只用知识库词覆盖密度、数字密度与病历结构词，**不使用文本长度**（长度会随输入漂移且两份语料长度本就分离，用它会在评测集上虚高）。
- **按准确率校准的置信度：**不再用"分数 < 25 就低置信"这类固定阈值。各方法分数量纲差异极大（实测 RRF 分数全部挤在 48.4~49.2，跨度不足 1 分），现改为在参考语料上分箱、实测每个分数档的 Top-1 准确率，再做保序回归平滑后分级。同一分数在两条通道下结论不同：TF-IDF 45 分在口语体档位实测 92%，在病历体档位只有 20%。
- **拒答与降级：**分类器概率低于 0.50 时该档实测准确率仅 55%（接近抛硬币），系统拒绝给结论并回落到检索候选，同时明确标注"降级候选、不作为结论"。
- **可解释检索：**从自然语言输入中抽取知识库症状词，以 precision、recall 和 F1 对证型条目排序，展示命中证据和未识别文本。
- **不确定性提示：**无命中、证据不足或候选接近时不伪装成确定答案；F1 是词项重合指标，不是诊断概率。
- **知识图谱：**将证型、症状、方剂条目连接成可交互图谱，呈现知识关系。
- **可选大模型：**只对检索证据做教学性摘要。API Key 从环境变量读取；默认不需要密钥即可使用本地功能。
- **安全边界：**不输出确诊结论、剂量或个体化用药建议，并提示咨询专业医疗人员。教学场景下，拒答机制本身即用于演示"证据不足时不下结论"的临床思维。

## 快速启动

需要 Python 3.9+。在本目录打开终端：

```bash
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
python server.py
```

浏览器打开 `main.html`。若浏览器限制本地文件跨域，可在另一个终端运行 `python -m http.server 5500`，再打开 `http://localhost:5500/main.html`。

可选模型配置：

```powershell
$env:DEEPSEEK_API_KEY="你的密钥"
$env:ZHIPU_API_KEY="你的密钥"
$env:MODELSCOPE_API_KEY="你的密钥"
python server.py
```

三家模型对同一份患者症状和知识库检索证据并发生成教学性摘要，接口以 `ai_comparison` 返回逐模型结果及状态。各家 API Key 独立配置；未配置或调用失败的模型会显示状态，不影响其他模型及本地匹配。不要把真实 API Key 写入源代码、提交到代码仓库或放进参赛压缩包。

可分别用 `DEEPSEEK_API_URL`/`DEEPSEEK_MODEL`、`ZHIPU_API_URL`/`ZHIPU_MODEL`、`MODELSCOPE_API_URL`/`MODELSCOPE_MODEL` 覆盖默认的兼容 Chat Completions 地址或模型名。ModelScope 默认模型名和可用模型取决于账号/API 服务支持情况。

## 算法流程

1. 输入按中英文逗号、顿号、分号和换行切分；对每个片段，用最长优先的知识库词项进行抽取。
2. 统计用户输入的已识别词项与各证型词项集合的交集。
3. `precision = 命中数 / 已识别输入词数`；`recall = 命中数 / 该证型词项数`；`F1 = 2PR/(P+R)`。
4. 按 F1 排序，返回前五条，并原样展示命中证据、未识别片段及知识库记录中的舌脉/方剂信息。
5. 若启用模型，仅将检索证据交给模型生成摘要；模型输出不作为检索评分，也不视为医学结论。

## 实测数据（当前版本，可追溯）

同一批方法在两种输入风格下结论完全相反，这是路由与校准的设计依据：

| 方法 | 口语体（教材 37 例）| 病历体（TCM-SD 去泄漏 683 例）|
|---|---|---|
| 词项 F1（keyword） | 67.6% | 3.9% |
| BM25 | 86.5% | 13.6% |
| TF-IDF 检索 | **91.9%** | 12.7% |
| RRF 融合 | 81.1% | 6.1% |
| TF-IDF+LR 分类器 | 5.4% | **93.0%** |

病历体一列的诚实口径（务必一并说明，不要只报 93.0%）：

- 该子集 683 例中，**单一证型"气滞血瘀"占 530 例（77.3%）**，即"永远回答气滞血瘀"就有 77.3% 的基线；
- 分类器 Top-1 93.0%，**仅高出多数类基线 15.7 个百分点**；macro-F1 为 71.4%，稀有证型（如肾阳虚 n=2、肺阴虚 n=2）波动极大；
- TCM-SD 官方划分不是患者级划分，测试集与训练集存在文本重叠：全量 553/5486 条，落到本子集内有 4 条，**已剔除后重测**（694 → 683），指标几乎不变，说明泄漏不是该分数的主要来源，但划分方式仍需在下一阶段修正。

### 大模型零样本基线（为什么不用大模型直接辨证）

通用大模型具备中医基础知识，但未见过本数据集的证型归一化规范，零样本直接提问的准确率显著低于域内训练的轻量分类器。三家模型使用完全相同的提示词与同一批样本：

| 方法 | 病历体全量 683 | 病历体抽样 42 | 教材体 37（口语）|
|---|---|---|---|
| DeepSeek 零样本 | **75.8%** | 50.0% | 40.5% |
| 智谱 GLM-4-Flash 零样本 | — | 35.7% | 37.8% |
| ModelScope Qwen 零样本 | — | 54.8% | 40.5% |
| 本地 TF-IDF 检索 | 12.7% | 19.1% | **91.9%** |
| 本地轻量分类器 | **93.0%** | 85.7% | 5.4% |

解读（三点都要说到）：

1. **病历体上分类器 93.0% vs DeepSeek 零样本 75.8%，领先 17.2 个百分点**；分类器高置信档（概率≥0.87，覆盖 62.2%）实测 99.1%，而大模型没有任何不确定性信号可用。
2. **口语体上反过来：三种大模型只有 37.8%~40.5%，而 TF-IDF 检索有 91.9%**。这说明按输入风格路由不只在本地方法之间成立，对大模型同样成立。
3. **抽样集与全量必须同时报**：抽样 42 条时 DeepSeek 仅 50.0%，全量 683 条是 75.8%。原因是分层抽样为保证每类都有样本而放大了稀有证型，全量中气滞血瘀独占 77.3%。只报一个数字会被质疑抽样偏差。

错误模式：大模型倾向把不同证型判为高频标签（智谱 42 条里 10 次答气血两虚；DeepSeek 与智谱都把中气下陷答成肾气虚），说明它不掌握该数据集的标注边界。

定位结论：**大模型在本作品中的正确角色是辅助——对检索证据做教学性摘要，而不是替代分类器。** 完整数据见 external_data/llm_baseline/。
路由与校准参数（可用 GET /api/calibration 原样取出）：

| 项目 | 值 | 依据 |
|---|---|---|
| 口语体主方法 | TF-IDF 检索 | 教材集 91.9%，同集合分类器仅 5.4% |
| 病历体主方法 | TF-IDF+LR 分类器 | 去泄漏 683 例 93.0%，同集合检索仅 12.7% |
| 风格判据 | 知识库词覆盖密度 + 数字密度 + 病历结构词 | 两份语料实测：覆盖 19.6% vs 2.6%、含数字 0% vs 95.8%；**刻意不用文本长度** |
| 风格判定准确率 | 教材体 37/37、病历体 5482/5486 | 另有 10 条人工边界用例，9 条判对；唯一漏判是 22 字短病历，方向为保守侧（走检索） |
| 置信度来源 | 分档实测准确率（保序回归平滑） | 口语体参考 37 条、病历体参考 683 条，各分 3 箱 |
| 分类器可靠档 | 概率 >= 0.87 | 该档实测 99.1%（覆盖 62.2%）|
| 分类器线索档 | 概率 >= 0.70 | 累计实测 97.4% |
| 分类器拒答线 | 概率 < 0.50 | 该区间实测仅 55.4%（接近抛硬币），9.5% 的样本落入此区间 |
| 分类器覆盖 | 16 / 37 个证型 | 未覆盖 21 类，见下方说明 |

**未覆盖的 21 个证型：**风寒感冒、风热感冒、肝火上炎、肾阴虚、湿热蕴脾、暑湿感冒、气虚感冒、肺气虚、脾阳虚、心气虚、胃火炽盛、心火亢盛、肺热炽盛、食积内停、膀胱湿热、肝血虚、寒湿困脾、风寒咳嗽、风燥伤肺、胃阴虚、寒邪客胃。

**覆盖缺口的含义：**以上 21 个证型永远不可能被分类器答出，只能由检索方法给出候选。因此界面对每一类都同时展示"置信标签 + 该档实测准确率"，不隐藏这个限制。

## 应用场景与需求分析

**学科专业：**中医学（中医诊断学 / 中医内科学方向）。

**具体应用场景：**

1. **教学场景**——中医诊断学课程中，学生需要把口语化的症状描述对应到规范证型，并理解每个证型的证据构成。传统方式是翻阅教材或证型手册逐条比对，检索一条证型通常需要数分钟。本工具把这一过程压缩到毫秒级，同时展示命中的症状词与舌脉依据，便于课堂演示与学生自查。
2. **科研场景**——在构建证型相关研究的数据集时，需要对病历文本做证型候选标注与一致性检查。本工具提供可追溯的候选排序、置信度分级与逐条原始输出，便于研究者复核与筛选，而不是把模型输出当作金标准。
3. **方法教学场景**——系统内置五种方法的横向对比、分布路由与置信度校准实验，可直接用于讲解"同一方法在不同数据分布下表现反转"这一常见误区。

**学科核心环节的痛点：**

- **术语鸿沟：**患者口语（"没胃口"）与规范证型术语（"食少纳呆"）之间缺少稳定映射，教材与学生之间缺乏可即时验证的对照工具。本工具内置 107 条口语→规范词映射。
- **证据不可追溯：**通用大模型能给出一个证型名，但无法说明依据了哪些症状，学生无法据此学习。本工具对每条候选展示命中的症状词与未识别文本。
- **过度自信：**多数工具不区分"有把握"与"在猜"。本工具用参考集实测准确率对置信度分级，并在证据不足时明确拒答。
- **分布失配被忽视：**口语描述与电子病历文本的分布差异极大，同一方法的准确率可以从 91.9% 跌到 12.7%。本工具把这一现象作为设计前提而非例外。

## 应用效果验证

| 对比项 | 传统方式 | 本工具 | 提升 |
|---|---|---|---|
| 单条证型检索耗时 | 翻阅教材/手册逐条比对，约数分钟 | TF-IDF 检索，约 0.05 秒 | 数量级提升 |
| 口语描述→规范证型 | 依赖个人经验，无稳定映射 | 107 条口语映射 + 检索，教材集 Top-1 91.9% | 有基线可依 |
| 证据可追溯性 | 无法说明依据 | 展示命中症状词与未识别文本 | 可教学、可复核 |
| 不确定性表达 | 无 | 置信度分级 + 拒答线（概率<0.50 时该档实测仅 55.4%） | 避免过度自信 |
| 大模型对照 | 无法比较 | 三家零样本实测：病历体 75.8%/35.7%/54.8%，口语体 37.8%~40.5% | 有量化依据 |

**效率与准确率的量化依据：**所有数字来自冻结测试集（教材 37 例、TCM-SD 去泄漏 683 例），脚本可复现，逐条原始输出已保存。

## 当前局限与完善路线

本版本已完成面向教学科研场景的知识检索、风格路由、置信度校准与拒答机制，并配套可复现的评测与基线对比。以下标出哪些已落实、哪些仍是待办（**均与临床有效性主张无关，本作品不作此类主张**）：

1. **问题定义：**已落实。界面与文档均明确任务为教学科研场景下的知识条目检索与候选排序，证型名不是诊断结论。
2. **数据治理：**部分做到。TCM-SD 来源与许可已注明（Borororo/ZY-BERT，CC-BY-SA）；但**尚无专家双人标注与仲裁**，本包是公开数据的二次使用，不是自建标注集。
3. **可信划分：**未做到，这是最大的方法学缺口。TCM-SD 官方划分非患者级，本版只能**度量并剔除**可见的文本重叠（553/5486，本子集内 4 条），无法修复患者级泄漏；macro-F1 有报告，但置信区间与患者级冻结测试集仍未建立。
4. **基线与消融：**已有五种方法横向对比与多数类基线（77.3%）对照；尚缺中文句向量检索，以及词项归一化、舌脉特征、重排模块的逐项消融。
5. **专家评审与安全：**不确定性已可测量——置信度按分档实测准确率校准，并设了拒答线（概率 < 0.50，该区间实测 55.4%）；尚缺专家盲评与错误类型学分析。仍未宣传任何临床准确率。
6. **演示叙事：**上述每个数字都可追溯：测试案例/eval_results.json（口语体）、测试案例/eval_real_results.json（病历体）、calibration_data.json（校准表与阈值）、external_data/llm_baseline/（大模型基线逐条原始输出）、GET /api/calibration（运行时原样暴露）。

本包使用了公开数据集 TCM-SD 的二次加工结果与自建教材体 37 例，**不含任何患者隐私数据**；不声称医学性能。知识库是原始演示条目，**应由专业教师复核后方可作为教学材料使用**。

## 可用于答辩的准确表述

“本作品实现了一个中医药知识库检索与可解释展示原型。当前版本基于 37 个证型条目，先按输入风格路由到检索或训练分类器，再用按准确率校准的置信度决定是否给出结论；同一批方法在口语体与病历体上表现相反（检索 91.9% vs 12.7%，分类器 5.4% vs 93.0%），因此不做单一主方法。所有分数均为词项或相似度指标，不是诊断概率。当前评测存在明确局限：TCM-SD 官方划分并非患者级划分，病历体测试集与训练集有约 10% 的文本重叠（已剔除后重测）；多数类基线达 77.3%，分类器高出基线 15.7 个百分点，macro-F1 仅 71.4%，稀有证型波动很大。下一阶段将建立经授权、专家标注的数据集，采用患者级独立划分，并在冻结测试集上与基线对比。”
