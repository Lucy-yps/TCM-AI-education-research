# 需求分析

## 一、项目背景与学科界定

**一级学科：**中医学
**二级方向：**中医诊断学 / 中医内科学
**核心环节：**证型辨识、证据追溯与辨证思维训练

中医药学的核心在于“辨证论治”。在中医诊断学教学与科研中，学生和研究者需要将患者口语化症状描述准确对应到规范证型，并理解每个证型的证据构成（症状、舌象、脉象、方剂）。然而，传统方式高度依赖教材翻阅和个人经验，效率低下且证据不可追溯。

本项目的核心定位是**面向中医专业教学与科研场景的知识检索与辨证训练辅助工具**（**非医疗器械，不提供临床诊断，不作为临床决策依据**）。服务对象为中医专业学生、规培医师与科研人员，用于证型知识查阅、证据追溯、辨证思维训练与检索方法教学。

## 二、应用场景界定

| 场景 | 使用者 | 传统做法 | 本工具做法 |
|---|---|---|---|
| 知识检索与自学 | 中医专业学生 | 翻阅教材/证型手册逐条比对，约数分钟/条 | 输入口语症状，毫秒级给出候选、证据与置信度 |
| 辨证思维训练 | 中医专业学生 | 优质病案题稀缺，编写一道带解析的题约需30~60分钟 | 从真实病历自动生成带解析的题目，支持题型自选 |
| 相似证型辨析 | 学生 / 规培医师 | 难以分清相近证型（如肝胃不和证/肝气犯胃证） | 基于病历统计对比差异特征，标注同义词对 |
| 科研标注辅助 | 研究者 | 人工逐条判读，无一致性工具 | 提供可追溯候选排序 + 置信度分级，供复核筛选 |
| 方法教学 | 教师 | 难以演示“分布失配”等抽象概念 | 内置五种方法对比与路由实验，可现场演示 |

## 三、学科核心痛点分析

### 3.1 痛点一：术语鸿沟（口语 vs. 规范术语）
患者口语（如“没胃口”“拉肚子”）与规范证型术语（如“食少纳呆”“大便泄泻”）之间缺少稳定映射。本工具内置 **107 条口语→规范词映射**，以知识库工程手段弥合这一鸿沟。

### 3.2 痛点二：证据不可追溯（黑盒模型的局限）
通用大模型能给出一个证型名，但无法说明依据了哪些症状，学生无法据此学习。本工具对每条候选展示**命中的症状词与未识别文本**，所有证据可追溯、可复现。

### 3.3 痛点三：过度自信（不确定性无法表达）
多数 AI 工具不区分“有把握”与“在猜”。本工具用参考集实测准确率对置信度分级，证据不足时明确**拒答**并降级为候选线索，这在教学场景中本身就是“证据不足时不下结论”的临床思维演示。

### 3.4 痛点四：分布失配被忽视（工程视角的核心发现）
口语描述与电子病历文本分布差异极大，同一方法的准确率可能发生反转：

| 方法 | 口语体（教材 37 例） | 病历体（TCM-SD 去泄漏 683 例） |
|---|---|---|
| TF-IDF 检索 | **91.9%** | 12.7% |
| TF-IDF+LR 分类器 | 5.4% | **93.0%** |

这一现象说明，在中医文本处理中**不存在单一的最优方法**。本工具通过知识库词覆盖密度、数字密度与病历结构词，实现可解释的输入风格判定（准确率 99.95%）。

### 3.5 痛点五：优质辨证练习题稀缺（教学核心痛点）
编写一道带解析的病案题约需 30~60 分钟，难以批量供给。本工具通过“真实病历 + 约束生成 + 结构校验”的机制，支持从 54,152 条真实病历中自动生成题目，目前题库已有 **151 题**，覆盖 **65/72 个核心证型**，核心校验通过率 100%。

## 四、需求调研依据

### 4.1 数据来源
| 数据 | 来源 | 许可 | 规模 |
|---|---|---|---|
| TCM-SD 电子病历 | Borororo/ZY-BERT 公开仓库 | CC-BY-SA | 54,152 条真实病历 |
| 教材体病例 | 本项目自建 | 项目自有 | 37 例 |
| 本草科普样例 | Wikimedia Commons | CC0 / CC-BY-SA 等 | 25 个参考样例 |

### 4.2 量化分析
- **术语覆盖率**：口语体 19.6% 字符可被知识库命中，病历体仅 2.6%。
- **数字密度**：教材体 0% 含数字，病历体 95.8% 含数字。
- **分布反转**：检索与分类方法在两种语料上表现完全相反（详见 3.4 节）。
- **出题成本**：单题 1,332 tokens，438 题约 1.5~2.9 元（大模型 API 成本）。

### 4.3 关于一线用户调研的说明
本团队三人均为**软件工程**专业，项目周期内聚焦于算法与系统原型开发，**本期未开展面向中医专业学生或教师的大规模正式问卷/访谈**。

为弥补这一短板，需求分析采用以下替代方式：
1. **教材研读**：系统查阅《中医诊断学》教材，结合真实教学场景提炼上述五类痛点；
2. **公开数据集量化分析**：基于 TCM-SD（54,152 条）与教材体 37 例，用真实数据论证分布失配与术语鸿沟；
3. **开发过程中的非正式交流**：团队与1位中医专业同学进行了非正式交流，对方均认同“口语与规范术语对照”是学习中的实际困难，且“带解析的病案练习题非常缺乏”。

正式的小规模教学试点已列为下一阶段计划（详见《项目实施计划》）。

## 五、目标用户与功能需求

### 5.1 目标用户
- **主要用户**：中医专业本科生、规培医师、中医诊断学教师
- **次要用户**：中医科研人员、数据标注人员

### 5.2 功能需求
| 功能模块 | 说明 | 优先级 |
|---|---|---|
| 知识检索与证型辨析 | 输入症状描述，输出候选证型、命中证据、未识别文本 | 高 |
| 输入风格路由 | 自动判定口语/病历体，展示判定依据 | 高 |
| 置信度分级与拒答 | 展示置信等级与该档实测准确率；证据不足时拒答并降级 | 高 |
| 辨证训练 | 从真实病历出题，覆盖 72 个证型，生成与判定分离 | 高 |
| 相似证型鉴别 | 选择两个易混证型，对比各自临床特征与共有症状 | 高 |
| 学习进度追踪 | 记录答题，统计薄弱证型与易混淆对 | 中 |
| 方剂治法联想 | 证型 ↔ 治法 ↔ 方剂对应练习 | 中 |
| 舌脉辨识 | 证型与舌脉表现对应练习（仅收录 ≥2 个鉴别性特征的证型） | 中 |
| 知识图谱 | 证型—症状—方剂交互图谱 | 中 |
| 本草科普样例库 | 25 个中草药外观参考图片与科普观察点 | 低 |
| 教学性证据摘要 | 三家大模型对同一证据并发生成摘要 | 低（可选） |

### 5.3 非功能需求
- **可解释性**：每个候选都能追溯到命中的症状词，每个置信等级都能追溯到参考集实测准确率。
- **可复现性**：所有实验脚本化，结果逐条落盘，任意结论可被第三方复核。
- **离线可用**：本地检索/分类/图谱/出题完全离线，仅大模型摘要与生成题目需联网。
- **安全边界**：不输出确诊结论、剂量或个体化用药建议。
- **轻量化**：分类器 7.6 MB，无需 GPU，普通笔记本即可运行。

## 六、需求结论

本工具聚焦中医教学与科研场景，以“**结论 + 证据 + 把握程度 + 复现路径**”为核心输出，解决传统方式中效率低、证据不可追溯、不确定性无法表达、分布失配被忽视、优质练习题稀缺五大痛点。

特别是面对“同一方法在不同数据分布下表现反转”这一中医文本处理中的核心难题，本项目没有追求单一的“最好模型”，而是以严谨的软件工程方法设计了可解释的分布路由与置信度校准机制，充分体现了 AI 技术与中医学科交叉的工程落地价值。
